## 📖 第一部分：什麼是 DP？

### 生活化比喻

想像你在爬一棟大樓，每到一層樓你就在牆上**刻下「從 1 樓到這裡最少走幾步」**。

當你要算「到第 10 層最少幾步」時，你不用重新從 1 樓走一次，只要**看第 8 層和第 9 層牆上刻的數字**，就能馬上算出來。

這就是 DP 的核心 —— **把算過的結果記下來，下次直接查表，不重算**。

### DP 的兩個必要條件

| 條件 | 白話說明 |
|------|---------|
| **最優子結構** | 大問題的最佳解，可以由小問題的最佳解組出來 |
| **重疊子問題** | 在解大問題的過程中，同樣的小問題會被重複算很多次 |

如果一個題目同時滿足這兩點 → 就適合用 DP。

### DP vs Greedy vs 暴力

| | 暴力（遞迴） | DP | Greedy |
|---|-------------|-----|--------|
| **策略** | 試所有可能 | 試所有可能 + 記住結果 | 只試當下最好的 |
| **正確性** | ✅ 一定對 | ✅ 一定對 | ❓ 不一定對 |
| **速度** | 最慢（指數級） | 快（多項式級） | 最快（線性級） |
| **本質** | DP 的前身 | 暴力 + 記憶化 | 不回頭的捷徑 |

**DP 本質上就是「聰明的暴力」**—— 該試的都試了，但不做重複的事。

### DP 的兩種實作方式

| 方式 | 方向 | 特色 |
|------|------|------|
| **Top-Down（記憶化遞迴）** | 從大問題往下拆 | 用遞迴 + map/陣列快取 |
| **Bottom-Up（遞推法）** | 從小問題往上算 | 用 for 迴圈 + dp 陣列 |

面試兩種都會用到，但 **Bottom-Up 更常見**，因為不怕 stack overflow，也更容易優化空間。

### DP 解題四步驟（萬用框架）

```
Step 1: 定義狀態 → dp[i] 代表什麼？
Step 2: 找出轉移方程式 → dp[i] 怎麼從前面的結果算出來？
Step 3: 確定初始值 → dp[0]、dp[1] 是多少？
Step 4: 確定遍歷順序 → 從前往後？從後往前？
```

**記住這四步，每題都先這樣想，不要直接寫 code。**

## 例題一：爬樓梯（LeetCode 70）— 最簡單的 DP

**題目**：你要爬 n 階樓梯，每次可以爬 1 階或 2 階，有幾種爬法？

```
n = 2 → 2 種（1+1 或 2）
n = 3 → 3 種（1+1+1 或 1+2 或 2+1）
n = 5 → 8 種
```

### 🧩 套用四步驟

**Step 1：定義狀態**

```
dp[i] = 爬到第 i 階的方法數
```

**Step 2：轉移方程式**

```
爬到第 i 階，只有兩種來源：
- 從第 i-1 階跨 1 步上來
- 從第 i-2 階跨 2 步上來

所以：dp[i] = dp[i-1] + dp[i-2]
```

**Step 3：初始值**

```
dp[1] = 1（只有一種：跨 1 步）
dp[2] = 2（兩種：1+1 或 2）
```

**Step 4：遍歷順序**

```
從 i=3 開始，往右算到 n
```

### 🚀 Go 解法

```go
func climbStairs(n int) int {
    if n <= 2 {
        return n
    }

    prev2 := 1 // dp[1]
    prev1 := 2 // dp[2]

    for i := 3; i <= n; i++ {
        curr := prev1 + prev2 // dp[i] = dp[i-1] + dp[i-2]
        prev2 = prev1
        prev1 = curr
    }

    return prev1
}
```

> 💡 這裡用了**空間優化**：不用整個 dp 陣列，只用兩個變數，因為每次只需要前兩個值。

### 📊 圖解

```
階梯:     1    2    3    4    5
方法數:   1    2    3    5    8
                ↑
              dp[3] = dp[2] + dp[1] = 2 + 1 = 3
              dp[4] = dp[3] + dp[2] = 3 + 2 = 5
              dp[5] = dp[4] + dp[3] = 5 + 3 = 8
```

```
                                    dp[5] = 8
                                   /         \
                             dp[4]=5        dp[3]=3
                            /      \        /      \
                       dp[3]=3  dp[2]=2  dp[2]=2  dp[1]=1
                       /    \
                  dp[2]=2  dp[1]=1

↑ 如果用遞迴暴力解，dp[2] 和 dp[3] 被重複算了好幾次
  DP 的意義就是：算過一次就記住，不再重算
```

## 例題二：打家劫舍（LeetCode 198）— 一維 DP 經典

**題目**：你是小偷，沿街有一排房子，每間有不同金額。但你**不能偷相鄰的兩間**（會觸發警報）。求你能偷到的最大金額。

```
nums = [1, 2, 3, 1]
答案：4（偷第 1 間 + 第 3 間 = 1 + 3 = 4）

nums = [2, 7, 9, 3, 1]
答案：12（偷第 1 間 + 第 3 間 + 第 5 間 = 2 + 9 + 1 = 12）
```

### 🧩 套用四步驟

**Step 1：定義狀態**

```
dp[i] = 從第 0 間到第 i 間，能偷到的最大金額
```

**Step 2：轉移方程式**

站在第 i 間房子前，你只有兩個選擇：

```
選擇 A：偷第 i 間 → 那第 i-1 間就不能偷 → dp[i-2] + nums[i]
選擇 B：不偷第 i 間 → 那最佳就是到第 i-1 間的結果 → dp[i-1]

dp[i] = max(dp[i-1], dp[i-2] + nums[i])
```

**Step 3：初始值**

```
dp[0] = nums[0]           （只有一間，就偷它）
dp[1] = max(nums[0], nums[1])  （兩間選大的）
```

**Step 4：遍歷順序**

```
從 i=2 開始，往右算到 n-1
```

### 🚀 Go 解法

```go
func rob(nums []int) int {
    n := len(nums)
    if n == 1 {
        return nums[0]
    }

    prev2 := nums[0]                // dp[0]
    prev1 := max(nums[0], nums[1])  // dp[1]

    for i := 2; i < n; i++ {
        curr := max(prev1, prev2+nums[i]) // dp[i]
        prev2 = prev1
        prev1 = curr
    }

    return prev1
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```

### 📊 圖解

`nums = [2, 7, 9, 3, 1]`

```
房子:     0    1    2    3    4
金額:   [ 2,   7,   9,   3,   1 ]

dp[0] = 2
dp[1] = max(2, 7) = 7

dp[2] = max(dp[1], dp[0] + nums[2])
      = max(7, 2 + 9)
      = max(7, 11) = 11         ← 偷第 0 間 + 第 2 間

dp[3] = max(dp[2], dp[1] + nums[3])
      = max(11, 7 + 3)
      = max(11, 10) = 11        ← 不偷第 3 間比較好

dp[4] = max(dp[3], dp[2] + nums[4])
      = max(11, 11 + 1)
      = max(11, 12) = 12        ← 偷第 2 間 + 第 4 間

答案：12 ✅
```

決策過程視覺化：

```
房子:  [2]   [7]   [9]   [3]   [1]
        偷         偷          偷     ← 最佳策略
        ↓          ↓           ↓
        2    +     9     +     1   = 12
```

## 例題三：不同路徑（LeetCode 62）— 二維 DP 入門

**題目**：一個 `m × n` 的格子，你在左上角，要走到右下角。每次只能往**右**或往**下**走一步。有幾種不同路徑？

```
m = 3, n = 7 → 答案：28
m = 3, n = 3 → 答案：6
```

### 🧩 套用四步驟

**Step 1：定義狀態**

```
dp[i][j] = 從左上角 (0,0) 走到 (i,j) 的路徑數
```

**Step 2：轉移方程式**

要到達 `(i,j)`，只能從上面 `(i-1,j)` 或左邊 `(i,j-1)` 走過來：

```
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

**Step 3：初始值**

第一行和第一列都只有 1 種走法（一直往右 or 一直往下）：

```
dp[0][j] = 1  （第一行）
dp[i][0] = 1  （第一列）
```

**Step 4：遍歷順序**

```
從左到右，從上到下
```

### 🚀 Go 解法

```go
func uniquePaths(m int, n int) int {
    dp := make([][]int, m)
    for i := range dp {
        dp[i] = make([]int, n)
    }

    // 初始化第一行和第一列
    for i := 0; i < m; i++ {
        dp[i][0] = 1
    }
    for j := 0; j < n; j++ {
        dp[0][j] = 1
    }

    // 填表
    for i := 1; i < m; i++ {
        for j := 1; j < n; j++ {
            dp[i][j] = dp[i-1][j] + dp[i][j-1]
        }
    }

    return dp[m-1][n-1]
}
```

### 📊 圖解

`m = 3, n = 4`

```
     j=0  j=1  j=2  j=3
i=0 [ 1,   1,   1,   1 ]   ← 第一行全 1
i=1 [ 1,   2,   3,   4 ]
i=2 [ 1,   3,   6,  10 ]
      ↑
    第一列全 1
```

以 `dp[2][2] = 6` 為例：

```
dp[2][2] = dp[1][2] + dp[2][1]
         =    3     +    3
         =    6

        ┌─────────┐
        │ dp[1][2] │  ← 從上面來（3 種）
        │    = 3   │
        └────┬─────┘
             ↓
┌─────────┐  ┌─────────┐
│ dp[2][1] │→│ dp[2][2] │
│    = 3   │  │   = 6   │
└─────────┘  └─────────┘
  ← 從左邊來（3 種）
```

## 例題四：零錢兌換（LeetCode 322）— 背包型 DP

**題目**：給你不同面額的硬幣 `coins` 和一個總金額 `amount`，算出湊成該金額所需的**最少硬幣數**。湊不出來回傳 -1。

```
coins = [1, 5, 11], amount = 15
答案：3（用三個 5 元）

注意：Greedy 在這題會失敗！
Greedy 會先拿 11 → 剩 4 → 拿四個 1 → 共 5 個
但最佳解是三個 5 → 共 3 個
```

### 🧩 套用四步驟

**Step 1：定義狀態**

```
dp[i] = 湊成金額 i 所需的最少硬幣數
```

**Step 2：轉移方程式**

對於金額 i，試每一種硬幣 coin：

```
dp[i] = min(dp[i], dp[i - coin] + 1)   （對所有 coin in coins）
```

意思：如果用了這個 coin，那剩下的金額是 `i - coin`，需要 `dp[i - coin]` 個硬幣，加上這一個就是 `dp[i - coin] + 1`。

**Step 3：初始值**

```
dp[0] = 0  （湊 0 元需要 0 個硬幣）
其餘 dp[i] = amount + 1  （設一個不可能的大值，代表「還沒算出來」）
```

**Step 4：遍歷順序**

```
從 i=1 算到 amount
```

### 🚀 Go 解法

```go
func coinChange(coins []int, amount int) int {
    dp := make([]int, amount+1)

    // 初始化：全部設為不可能的大值
    for i := range dp {
        dp[i] = amount + 1
    }
    dp[0] = 0 // 湊 0 元需要 0 個硬幣

    for i := 1; i <= amount; i++ {
        for _, coin := range coins {
            if coin <= i && dp[i-coin]+1 < dp[i] {
                dp[i] = dp[i-coin] + 1
            }
        }
    }

    if dp[amount] > amount {
        return -1 // 湊不出來
    }
    return dp[amount]
}
```

### 📊 圖解

`coins = [1, 5, 11]`, `amount = 15`

```
金額:  0   1   2   3   4   5   6   7  ...  11  12  13  14  15
dp:  [ 0,  1,  2,  3,  4,  1,  2,  3, ...,  1,  2,  3,  4,  3 ]
                              ↑                                ↑
                          用 1 個 5 元                     用 3 個 5 元
```

以 `dp[15]` 為例，試每一種硬幣：

```
coin=1:   dp[15] = min(dp[15], dp[14] + 1) = min(∞, 4+1) = 5
coin=5:   dp[15] = min(5,      dp[10] + 1) = min(5, 2+1) = 3  ⭐
coin=11:  dp[15] = min(3,      dp[4]  + 1) = min(3, 4+1) = 3

dp[15] = 3  ✅
```

### 🚨 為什麼 Greedy 在這題失敗？

```
Greedy：先拿最大的 11 → 剩 4 → 拿四個 1 → 共 5 個硬幣
DP：    三個 5 元 → 共 3 個硬幣

Greedy 每步選最大面額，但這不一定是全局最優！
這就是為什麼零錢問題要用 DP 而不是 Greedy。
```

## 🧠 第三部分：心法整理

### 1. DP 四步驟口訣

```
定狀態 → 寫轉移 → 設初值 → 定順序
```

每題都先在紙上把這四個寫出來，再寫 code。如果這四步想不清楚，code 一定寫不對。

### 2. 看到什麼關鍵字想 DP？

- 「**最少/最多/最長/最短**」→ 最優化問題
- 「有**幾種方法**」→ 計數問題
- 「**能不能**達成」→ 可行性問題
- 「**不能選相鄰的**」→ House Robber 型
- 「**子序列/子陣列**」→ 字串 DP

### 3. 空間優化的判斷

如果 `dp[i]` 只依賴 `dp[i-1]` 和 `dp[i-2]` → 可以只用兩個變數，不用整個陣列。

```go
// 原始版
dp := make([]int, n)

// 優化版（只用兩個變數）
prev2, prev1 := dp初始值
for i := 2; i < n; i++ {
    curr := 用 prev1 和 prev2 算
    prev2 = prev1
    prev1 = curr
}
```

面試時先寫陣列版，面試官問能不能優化再改。

### 4. DP 的學習路線圖

| 階段 | 題型 | dp 維度 | 代表題 |
|------|------|---------|--------|
| **入門** | 爬樓梯、費氏數列 | 1D | LeetCode 70, 509 |
| **基礎** | House Robber、最大子陣列 | 1D | LeetCode 198, 53 |
| **進階** | 格子路徑、背包 | 2D | LeetCode 62, 322 |
| **字串** | 最長回文、編輯距離 | 2D | LeetCode 5, 72 |
| **挑戰** | 區間 DP、狀態壓縮 | 2D+ | 面試很少考 |

### 5. 「想不到轉移方程式」怎麼辦？

**試試這個思路**：站在第 i 個位置，問自己「**我是從哪裡來的？**」

- 從 i-1 來？→ `dp[i-1] + 某個值`
- 從 i-2 來？→ `dp[i-2] + 某個值`
- 從所有 j < i 來？→ `min/max(dp[j] + 某個值)`

大部分一維 DP 的轉移方程式，都是這三種之一。

### 6. Top-Down vs Bottom-Up 選擇

| 情境 | 建議 |
|------|------|
| 初學者 / 先求正確 | Top-Down（遞迴 + 記憶化）比較直覺 |
| 面試 / 追求效率 | Bottom-Up（for 迴圈）更安全 |
| 狀態空間很大但實際用到的少 | Top-Down（只算需要的） |
