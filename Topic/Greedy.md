# Greedy（貪心演算法）完整教學

---

## 📖 第一部分：什麼是 Greedy？

### 生活化比喻

想像你在超市結帳，店員要找你 **41 元零錢**，手上有 25、10、5、1 元硬幣。

店員不會去想「所有可能的硬幣組合中，哪一種用最少硬幣」，他只會：

- 先拿一個 **25**（能拿最大的就拿）→ 剩 16
- 再拿一個 **10** → 剩 6
- 再拿一個 **5** → 剩 1
- 最後拿一個 **1** → 剩 0

**每一步都選「當下最好的」，不回頭，不考慮未來。** 這就是 Greedy。

### Greedy vs DP 的差別

| | Greedy | DP |
|---|--------|-----|
| **決策方式** | 每步選當下最佳，不回頭 | 考慮所有子問題，選全局最佳 |
| **正確性** | 不一定能得到最佳解（要能證明才行） | 一定能得到最佳解 |
| **速度** | 通常更快（O(n) 或 O(n log n)） | 通常較慢（O(n²) 或更高） |
| **難點** | 想到貪心策略 + 證明它是對的 | 定義狀態 + 寫出轉移方程式 |

### 什麼時候能用 Greedy？

Greedy 能用的前提是題目具有 **「貪心選擇性質」**：

> **局部最優選擇 → 能導出全局最優解**

白話說：每一步選最好的，最後結果也是最好的。

不是所有題目都有這個性質！所以 Greedy 最難的地方不是寫 code，而是**判斷這題能不能用 Greedy**。

### Greedy 的常見套路

| 套路 | 策略 | 代表題 |
|------|------|--------|
| **排序 + 貪心** | 先排序，再逐一做最佳選擇 | 區間排程、分發糖果 |
| **從最大/最小開始選** | 每次選當前最有利的 | 零錢找零、跳躍遊戲 |
| **兩端比較** | 從兩邊比較，選較有利的一端 | 分發餅乾 |

## 例題一：分發餅乾（LeetCode 455）— Easy 入門

**題目**：你是家長，手上有一些餅乾，每塊餅乾有大小 `s[j]`。每個小孩有一個「滿足度」`g[i]`，只有餅乾大小 `s[j] >= g[i]` 時，小孩才會滿足。求最多能滿足幾個小孩？

```
g = [1, 2, 3]    ← 小孩的滿足度
s = [1, 1]       ← 餅乾大小

答案：1（只有一個小孩能被滿足）
```

### 🤔 貪心策略

**「最小的餅乾餵最容易滿足的小孩」**

為什麼？因為大餅乾留給胃口大的小孩更有價值，把大餅乾浪費在胃口小的小孩身上不划算。

步驟：

1. 把小孩的滿足度**排序**（小 → 大）
2. 把餅乾大小**排序**（小 → 大）
3. 從最小的開始配對

### 🚀 Go 解法

```go
import "sort"

func findContentChildren(g []int, s []int) int {
    sort.Ints(g) // 小孩滿足度排序
    sort.Ints(s) // 餅乾大小排序

    child := 0
    cookie := 0

    for child < len(g) && cookie < len(s) {
        if s[cookie] >= g[child] {
            child++ // 這個小孩被滿足了，換下一個小孩
        }
        cookie++ // 不管有沒有滿足，這塊餅乾都用掉了
    }

    return child
}
```

### 📊 圖解步驟

`g = [1, 2, 3]`, `s = [1, 1]`

排序後不變：`g = [1, 2, 3]`, `s = [1, 1]`

```
小孩:    [1,  2,  3]
          ↑
        child=0

餅乾:    [1,  1]
          ↑
        cookie=0
```

#### Step 1：餅乾 1 >= 小孩 1 ✅ 配對成功

```
小孩:    [1,  2,  3]
              ↑
            child=1

餅乾:    [1,  1]
              ↑
            cookie=1

滿足人數 = 1
```

#### Step 2：餅乾 1 < 小孩 2 ❌ 配不上

```
小孩:    [1,  2,  3]
              ↑
            child=1（不動）

餅乾:    [1,  1]
                  ↑
                cookie=2 → 超出範圍，結束

滿足人數 = 1
```

#### 最終答案：`1` ✅

### 🤔 為什麼這個 Greedy 是正確的？

**反證法**：假設我們不用最小的餅乾餵最小胃口的小孩，而是用一塊大餅乾去餵他。

那原本可以被大餅乾滿足的「大胃口小孩」就沒餅乾了 → 總滿足人數只會更少或不變，不會更好。

所以「小餅乾配小胃口」永遠不會比其他策略差 → Greedy 正確 ✅

## 例題二：跳躍遊戲（LeetCode 55）— Medium 經典

**題目**：給你一個陣列 `nums`，每個元素代表你在那個位置**最多能往前跳幾步**。判斷你能不能從索引 0 跳到最後一個位置。

```
nums = [2, 3, 1, 1, 4]  → true（可以到達）
nums = [3, 2, 1, 0, 4]  → false（卡在索引 3）
```

### 🤔 貪心策略

**「記錄目前能到達的最遠位置，如果能覆蓋到終點就成功」**

不需要真的去「跳」，只要一直更新「我最遠能到哪裡」就好。

### 🚀 Go 解法

```go
func canJump(nums []int) bool {
    maxReach := 0 // 目前能到達的最遠位置

    for i := 0; i < len(nums); i++ {
        if i > maxReach {
            return false // 走不到這個位置，卡住了
        }
        reach := i + nums[i]
        if reach > maxReach {
            maxReach = reach // 更新最遠能到的位置
        }
    }

    return true
}
```

### 📊 圖解步驟

#### ✅ 成功案例：`nums = [2, 3, 1, 1, 4]`

```
索引:    0    1    2    3    4
值:    [ 2,   3,   1,   1,   4 ]
目標:                         ↑（要到這裡）
```

```
i=0: maxReach = max(0, 0+2) = 2     能到索引 2
     [===========]
      0    1    2    3    4

i=1: maxReach = max(2, 1+3) = 4     能到索引 4！
     [=======================]
      0    1    2    3    4

i=2: maxReach = max(4, 2+1) = 4     沒更遠
i=3: maxReach = max(4, 3+1) = 4     沒更遠
i=4: 到達終點！

答案：true ✅
```

**關鍵時刻在 i=1**：nums[1]=3，讓 maxReach 一口氣跳到 4（終點），後面只是驗證而已。

#### ❌ 失敗案例：`nums = [3, 2, 1, 0, 4]`

```
索引:    0    1    2    3    4
值:    [ 3,   2,   1,   0,   4 ]
目標:                         ↑（要到這裡）
```

```
i=0: maxReach = max(0, 0+3) = 3     能到索引 3
     [==================]
      0    1    2    3    4

i=1: maxReach = max(3, 1+2) = 3     沒更遠
i=2: maxReach = max(3, 2+1) = 3     沒更遠
i=3: maxReach = max(3, 3+0) = 3     nums[3]=0，卡住了！
     [==================]
      0    1    2    3    4
                     ↑ 最遠只到這裡

i=4: i(4) > maxReach(3) → return false 🛑

答案：false ✅
```

**關鍵時刻在 i=3**：nums[3]=0，表示站在索引 3 完全跳不動，而之前累積的 maxReach 也只到 3，所以永遠到不了索引 4。

## 🧠 第三部分：心法整理

### 1. Greedy 最難的不是寫 code，是「想到策略 + 證明正確」

面試時如果你選擇用 Greedy 解題，面試官**一定會問你為什麼這樣是對的**。

準備兩種說法：

- **直覺說法**：「因為 _____ 不可能比 _____ 更好」
- **反證法**：「假設不這樣做，結果只會更差或一樣，不會更好」

### 2. 辨識題型的關鍵字

看到這些，先想 Greedy：

- 「**最多/最少**能完成幾個」
- 「**能不能**到達某個目標」
- 「**最佳排程/分配**」
- 題目有「**排序後就變簡單**」的感覺

### 3. Greedy 的萬用解題流程

```
Step 1: 排序（大部分 Greedy 題都需要先排序）
Step 2: 逐一遍歷，每步做當下最好的選擇
Step 3: 更新答案
```

### 4. 「Greedy 不對就換 DP」

如果你想了一個 Greedy 策略，但舉了一個反例就破功了 → 那這題大概要用 DP。Greedy 和 DP 經常是同一類題目的兩種解法，差別在於 Greedy 只在特定條件下成立。

### 5. 常見的 Greedy 排序策略

| 題目類型 | 排序方式 |
|---------|---------|
| 區間排程 | 按**結束時間**排序 |
| 分配問題 | 按**需求**或**供給**排序 |
| 最小成本 | 按**成本**排序 |
| 字串拼接 | 按**自定義比較**排序 |
